# 民声有回应 · 政务服务好差评

本地可运行的课程实验网站。覆盖多渠道评价、差评核实整改、群众确认、公开榜单和可用性问卷。使用 Flask、SQLite、原生 JavaScript、ECharts；前端依赖随源码分发，运行时不依赖公共 CDN。

## 启动

需要 Python 3.11 或更新版本。Windows 在本目录运行 `powershell -File start.ps1`；macOS / Linux 运行 `sh start.sh`。首次启动需要联网安装 requirements.txt 中的依赖。

打开 <http://localhost:5100>。同一局域网的其他设备访问 `http://本机局域网IP:5100`。防火墙如提示，只允许需要使用的专用网络。二维码采用当前网站地址，跨设备使用时应从局域网地址生成。

Docker 可选：`docker compose up --build`。数据库持久化在独立的 `feedback-data` 卷。停止使用 `docker compose down`，不加 `-v` 即保留数据。

默认端口 5100，可通过 `PORT` 环境变量修改。监听地址由 `HOST` 配置，默认 `0.0.0.0`。独立会话 Cookie 名为 `gov_feedback_session`，不会与面试系统的登录冲突。

## 完整演练

1. 群众登录，在“我的办件”创建场景 A、B 或 C 的模拟办件。
2. 选择办件服务、办事指南或大厅窗口，提交五级评价。每个办件的每个对象只能评价一次。
3. 1–2 星自动生成待受理工单。评价后可填写五题课程改编问卷或标准 SUS 十题问卷，以及 NASA-TLX 六维度评分；也可稍后填写。
4. 管理员派发给责任部门的整改专员。
5. 专员核实。有效差评进入整改；无效差评填写依据后向群众解释。不能单凭“材料不全”自动驳回。
6. 有效差评先保存整改方案，再提交处理反馈。
7. 群众接受结果后办结；不接受可退回整改或重新核实。
8. 在公开榜单查看变化；管理或监督角色在“交互评估”查看分组统计并导出 CSV。

短信不接入真实运营商。生成邀请后，信息进入本地模拟收件箱；链接及二维码可实际打开，绑定本人账号，7 天有效。

## 数据与统计口径

首次启动生成 64 个办件、58 条评价和对应问卷等教学数据。固定随机种子使分数可复现，日期相对初始化当天生成。所有预置数据均为合成数据，不能当作真人调查。新建实验办件也明确标记为模拟。

- 好评为 4–5 星；差评为 1–2 星；3 星单列。
- 五级满意度课程分值：5/4/3/2/1 星对应 10/8/6/3/0 分。
- 整改率：已由群众确认办结的有效差评 / 已核实有效差评。无分母时显示“—”，不显示虚假的 100%。无效差评解释归档不计入整改完成。
- 课程五题均为正向题，分数为 `(原始总分 - 5) * 5`，取值 0–100。它是明确标注的课程改编版，不能套用标准 SUS 的行业基准。
- 标准 SUS 十题：奇数题减 1、偶数题用 5 减原值，求和乘 2.5。不同问卷版本不混合统计。
- Raw NASA-TLX：六维 0–100 评分取平均。表现维度以 0=完美完成、100=完全失败统一负荷方向。
- 默认工单期限为 5 个自然日的教学规则，不代表任何实际政务部门的期限。

运行数据和自动生成的会话密钥保存在 `.local/`，不会提交 GitHub。清理数据库会丢失实验记录，应先备份整个 `.local` 目录。没有自动删除或覆盖用户数据的启动行为。

## 关键接口

所有写请求需要先获取 `/api/session`，随后在 `X-CSRF-Token` 中携带返回的令牌。登录后令牌重新生成，客户端应更新。

| 方法及路径 | 功能 | 权限 |
|---|---|---|
| GET /api/session | 当前会话和 CSRF 令牌 | 公开 |
| POST /api/register, /api/login, /api/logout | 群众注册、登录、退出 | 注册仅创建群众角色 |
| GET/POST /api/cases | 列表、创建模拟办件 | 按角色和归属过滤 |
| GET/POST /api/evaluations | 记录、提交评价 | 写入仅群众本人 |
| GET /api/tickets, /api/tickets/{id} | 工单和事件时间线 | 群众本人、部门工作人员或管理监督 |
| POST /api/tickets/{id}/actions | 派单、核实、方案、反馈、接受、退回、催办 | 根据动作检查角色与状态 |
| POST /api/surveys | 问卷计分与保存 | 对应评价的群众本人 |
| GET/POST /api/messages | 模拟邀请 | 归属与部门校验 |
| GET /api/invite/{token} | 校验补评邀请 | 本人、有效期内 |
| GET /api/public/stats | 区域、时间、对象筛选的榜单 | 公开，返回字段不含用户身份 |
| GET /api/analytics | 同版本内分组统计 | 管理、监督 |
| GET /api/export/{kind} | surveys / tickets / evaluations CSV | 管理、监督 |

工单动作提交 `action`、`version`、`detail`，派单还需要 `assignee_id`。过期版本返回 409；权限不符返回 403；格式或业务条件不符返回 400。评价与工单创建、状态更新与事件写入都在同一事务中。

## 开发验证

运行 `python -m unittest discover -s tests -v`。可选安装 coverage 后运行 `coverage run --source=app,db,services -m unittest discover -s tests` 与 `coverage report`。检查使用临时数据库，不会写入实际实验数据库。包含 100 个并发测试客户端的唯一评价提交与持久化核对；这不是公网生产容量承诺。

本仓库仅包含网站源码、自动化检查代码与运行说明。课程报告、原型截图和建模材料保留在本地，不随仓库发布。

## 边界

本项目是局域网课程模拟，不连接真实政务平台，不发送真实短信，不使用真实身份证或办件数据。未实现的选做项包括付费大模型自动甄别与 WebSocket 榜单推送；榜单重新进入或筛选时刷新。正式互联网运行还需 HTTPS、账户治理、登录限速、审计与运维方案。

第三方库许可证见 `static/vendor/`。自行编写的代码采用 MIT 许可证。

## 本轮交互改进

- 登录首页按角色呈现待办。群众可直达待评价、待确认和处理中的反馈；工作人员可直达核实、整改与 24 小时内到期筛选。公共统计仍在“服务总览”。
- 评价对象带说明，渠道从办件或邀请自动带入；原因标签随对象和满意度更新，切换时保留补充文字。相同办件同一对象仍只允许评价一次。
- 评价提交先显示编号、工单入口与下一步。“自愿填写问卷”为独立操作，关闭回执不会丢失服务评价。
- 工单详情突出当前责任人、更新时间、下一步和是否需要本人操作；说明解释与有效差评整改采用不同阶段名称。

升级无需重建数据库；停止旧进程后拉取源码，再按原启动方式运行即可。
